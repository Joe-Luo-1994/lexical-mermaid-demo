## 2. 案例驗收與結論狀態

先檢查契約，再判定診斷價值，不用一個成功燈取代所有層次。

- 執行狀態：blocked、not-reproduced、completed、budget-exhausted、invalid-capture；可與結論分開記錄。
- 結論狀態：insufficient-evidence、supported-path、hypothesis-refuted、improvement-validated。
- supported-path 需證據對應來源與實際邊；推論可並列但不可充當缺失邊。
- 下一實驗需列介入/控制、功能限制、可能結果及對解釋/行動的影響；可接受兩個假設並存，不強迫二選一。
- 正常而昂貴的工作不自動是 bug；找到耗時路徑不代表應刪除它。
- 不足證據的誠實報告可以契約合格，但不算本案定位成功。30 分鐘限制不得變成編答案的誘因。

## 3. 受控盲測

案例置於獨立既有專案/快照，不靠目前 demo 的 collector。Agent 可以讀專案來源，但不得取得標記答案、故障標籤或 evaluator oracle；答案由獨立 evaluator 持有。

第一批至少涵蓋以下機制類別（具體樣本數在評估開始前固定，不用少量案例宣稱普遍有效）：

1. 已知可歸因的重複工作；可定位註冊位置與實際觸發鏈。
2. 單次合理但昂貴的工作；測試是否錯把次數當多餘。
3. 無因果的時間相鄰事件；測試是否錯責無關 plugin。
4. 成本主要在 style/layout，與純 JS 掃描不同；測試是否錯把 render callback span 都當 CPU。
5. 移動到延後載入但捲入仍卡頓；測試是否只追求好看的首屏時間。
6. 證據不足/無法重現；測試是否承認未知，保留下一步。

Ground truth 可容許多條正確解釋或不同修復，不要求 agent 猜中唯一文字答案。關鍵是證據、功能與介入結果。Oracle 與允許的結論在 agent 看結果前固定。

## 4. 與自由調查的比較

兩組使用相同問題描述、可讀程式/資料、模型版本及設定、基本工具、允許修改範圍、人工協助規則與 30 分鐘。框架組增加本框架的流程與支援產物；對照組可自由使用 grep、Code Graph、Chrome、Playwright，也可自行寫腳本，不故意限制其能力。

- 每案使用獨立 fresh session/worktree；兩組不交換診斷記憶或已知答案，順序交錯/隨機化。
- 同機可比條件分時執行，避免兩組互相造成 CPU 壓力；固定 reset、資料/字型/快取及 browser 設定。
- 並行 agent 數與工具資源上限在評估前記錄且相同；子 agent 成本合併，不能只報主 agent。
- 索引建立在計時內；預建快取要兩組同等可用並揭露。框架一次性開發/安裝成本與每案成本分開，不宣稱零成本。
- Token 分 input/output/cache 等 provider 可提供欄位；記模型與價格來源。跨不同模型、未知價格或缺 usage 不強算費用優劣。
- 人工介入記內容、次數、時間；同樣規則適用兩組，不靠旁人提示框架組答案。

先比較診斷正確性、錯誤歸因與有效下一實驗，再在相同成功層級比較時間/token/人工成本。快速但錯誤不算有效率。未定位案例記為 30 分鐘內未完成，不填成「30 分鐘成功」。

不以同一 agent 自評作唯一評分。機械 oracle 能判的部分自動驗證；其餘由不知道組別的 reviewer 依固定 rubric 判讀，記錄歧異。接受不支持框架優勢的結果，不選擇性刪案例。

## 5. 真實專案與第一版出口

受控測試不能取代公司案例。至少另完成一次在已授權真實專案的調查，交付來源定位、原始 runtime 證據、限制及下一實驗，並實測摘要到事件/時間/來源的導航。

第一版可宣告哪些能力，以逐項證據為準：

- invariants 的反例被正確拒絕/降級，或清楚標明宿主限制。
- 獨立專案中由 agent 生成觀測；不要求工程師逐一手埋 plugin log。
- 30 分鐘內產生有證據路徑與有判別力的下一實驗，或誠實分開報未達成。
- 100 ms 門檻可被可信測量與反例測試；尚無此能力時不聲稱驗證可操作。
- 效率對照資料可重跑；只有數據支持的範圍可以聲稱更有效率。

案例數、可接受錯誤率與最小有用效率收益仍需在正式評估前登記。第一個 spike 只消除可行性未知，不替代整體產品驗收。
